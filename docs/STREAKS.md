# Daily streaks

`learning_stats` remains Haru’s single per-user progress row. The streak migration adds its learning timezone, qualifying-date anchor, freeze balance, XP total, and update time; daily activity and idempotent event tables provide the history. Authenticated users can read their own progress, while mutations run through security-definer database functions and the trusted conversation completion path. The previous per-reply UTC streak cannot prove qualifying days, so rollout clears its active count and preserves the old value in `legacy_current_streak`; the historical longest count is preserved. XP and total practice-day counts start at rollout because old conversations are not backfilled without the new three-reply verification. Before any new qualifying event, rollback can restore `current_streak` from `legacy_current_streak`. After new events, retain the new history and reconcile rather than restoring the stale value.

A conversation qualifies only after the server has stored at least three meaningful learner replies and the user finishes it. A lesson-linked conversation is recorded as a guided mission. Reopening or finishing the same conversation twice does not award XP twice. Every qualifying activity grants 15 XP; milestones at 3, 7, 14, 30, 100, and 365 days grant an additional 10 XP per milestone day. A 7- or 30-day milestone also grants one free freeze when the balance is below two.

The device’s IANA timezone is saved to `learning_stats` before loading the summary. Activity timestamps stay in UTC, and PostgreSQL assigns each event’s learning date using the saved timezone. Timezone changes affect future events and do not rewrite historical learning dates. The legacy `last_practice_date` remains for the existing UTC reply counter; it is not the streak date.

New accounts receive one free freeze. Existing accounts receive one launch freeze. The balance is capped at two; a freeze is consumed automatically for each missed day before the current local day. Any uncovered missed day breaks the current streak, while longest streak never decreases. There is no paid protection.

The existing app does not yet have a server-verifiable standalone lesson completion or vocabulary review session, so marking a saved phrase learned and finishing local lesson preparation do not qualify by themselves. Daily notifications are opt-in during onboarding or in Profile, scheduled locally at the selected time in device time, and can be turned off in Profile. They do not affect streaks.

Apply `202611060001_daily_streaks.sql` after the existing migrations. The repository’s isolated `npm run test:db` suite covers RLS, completion thresholds, duplicate and concurrent events, freezes, milestones, timezone changes, DST, and date boundaries.
